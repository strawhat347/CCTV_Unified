================================================================================
 CCTV UNIFIED SURVEILLANCE — WORKFLOW v2
 (Backend Service + Chromium-Shell Desktop Client)
================================================================================

WHAT CHANGED FROM v1
--------------------------------------------------------------------------------
v1 assumed a single process: GUI talks to `db/*.py` and `pipeline/*.py`
directly, on one machine. That only works for one user on one box.

v2 splits the system into two independently-runnable pieces structured
across clear architectural layers:

  1. BACKEND SERVICE  — owns MySQL, owns the detection pipeline, enforces
                         authentication & RBAC, and exposes everything over
                         HTTP/WebSocket. Runs headless, indefinitely, on a
                         server (or localhost for demo).

  2. DESKTOP CLIENT    — a Chromium-based shell (pywebview or Electron)
                         rendering HTML/JS/CSS. Holds NO business logic,
                         NO SQL, NO direct DB access. Talks to the backend
                         only via `fetch()` / WebSocket, same shape as how
                         the Steam client talks to Steam's backend.

This is the same "swap without rewrite" philosophy you already used for
mock/real camera sources and mock/real registry — just applied one layer
up, to the client shell itself. SHELL becomes a config toggle exactly
like MODE was.

--------------------------------------------------------------------------------
DESIGN PRINCIPLES & LAYERED ARCHITECTURE
--------------------------------------------------------------------------------
The system is partitioned into modular, decoupled layers with a clear build progression:
  • Layer 1 (Data): MySQL 8.0, Thread-safe Connection Pool, DAOs.
  • Layer 2 (Core CV & Engine): Video capture, YOLOv8 + Hierarchical detection,
    SAHI 1280px Tiling, 5-stage preprocessor, Dual-Path PaddleOCR, Rule Engine.
  • Layer 3 (API & Communication): FastAPI REST endpoints, Pydantic schemas,
    WebSocket real-time alert/detection bus.
  • Layer 4 (Presentation / GUI): Lightweight Chromium Desktop Client
    (pywebview/Electron) with zero-leak bounded DOM.
  • Layer 5 (Edge AI Copilot): Local Quantized LLM (Ollama / Phi-3 / Qwen2) for
    natural language incident query & triage.
  • Layer 6 (Enterprise Security & Hardening): Bcrypt hashing, JWT Bearer tokens,
    Role-Based Access Control (Admin/Operator/Auditor), AI prompt sandboxing,
    audit logging, tokenized stream protection.
  • Layer 7 (Packaging & Deployment): Docker Compose & PyInstaller standalone bundle.

Guiding Principles:
- ABCs lock down every boundary that might later be swapped: camera
  source, detector, OCR engine, registry — and now also the CLIENT SHELL.
- GUI/client code NEVER touches SQL or model code directly — enforced
  structurally now, not just by convention, because the client physically
  cannot reach MySQL (no driver, no credentials, no network path to DB).
- The backend is the only source of truth. The client is a thin,
  disposable viewer — if it crashes or leaks memory, no data is lost or
  corrupted, since nothing lives only in client memory.
- Server-side validation and authentication are mandatory on every API input.
  The client is an untrusted boundary the same way a browser tab is.
